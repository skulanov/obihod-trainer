# Обиходный тренажёр

Веб-приложение (SPA) для обучения распознаванию на слух гласов (1–8) и колен церковных напевов в двух категориях: **Тропари** (`trop`) и **Стихиры** (`stih`).

Приложение разработано для публикации на **GitHub Pages** без бэкенда и регистрации: история занятий, настройки и незавершённая сессия хранятся локально в браузере пользователя (IndexedDB + localStorage).

## Возможности MVP

- **Каталог и открытое изучение:** дерево «Категория → Глас → Колено», единая нотация (`1`, `1a`, `2`, `2a`, `3`, `4`, `5`, `К (конечное)`), последовательное прослушивание колен.
- **Настройка викторины:** выбор категории, одного или нескольких доступных гласов, конечный и бесконечный режимы, честная работа с неполной аудиотекой.
- **Экран задания и проверка:** воспроизведение без раскрытия имени файла и ответа до проверки, раздельная оценка гласа и колена, постоянный полный список из 8 колен, нормализация ввода с клавиатуры (`1a`/`1а`, `2a`/`2а`, `К`/`к`/`K`/`k`).
- **Итоги и статистика:** отчёты по завершённым занятиям, раздельная точность по гласу и колену с первой попытки, список сложных колен со ссылкой на прослушивание в каталоге, срезы по категориям, гласам и коленам.
- **Автоматическая валидация аудиотеки и CI/CD:** проверка имён MP3 и конфликтов при сборке и перед публикацией на GitHub Pages.

## Локальный запуск

Требуется Node.js 20+.

```bash
npm install
npm run build:catalog
npm run dev
```

Приложение откроется на `http://localhost:3000`.

## Проверки, тесты и сборка

```bash
# Проверка типов TypeScript
npm run lint

# Автотесты парсера, нормализации, движка викторины и статистики
npm test

# Валидация public/audio/ и генерация public/data/catalog.json
npm run build:catalog

# Полная сборка (включает генерацию каталога и сборку Vite)
npm run build
```

## Добавление новых аудиозаписей

Исходный код менять не нужно:

1. Поместите MP3-файл в папку `public/audio/`.
2. Имя файла должно строго соответствовать формату:
   ```text
   <category>_<glas>_<knee>.mp3
   ```
   - `category`: `trop` или `stih`
   - `glas`: одна цифра от `1` до `8`
   - `knee`: одно из `1`, `1a`, `2`, `2a`, `3`, `4`, `5`, `К`
   - Рекомендуемый единый стиль для новых файлов: `trop_1_1a.mp3`, `trop_8_К.mp3`, `stih_6_2a.mp3`.
3. Выполните `npm run build:catalog` (или отправьте изменения в ветку `main` — GitHub Actions выполнит проверку автоматически).
4. При некорректном имени или дубликате после нормализации (например, `trop_2_1a.mp3` и `trop_2_1а.mp3`) сборка завершится с ошибкой, и публикация на GitHub Pages будет остановлена.

## Публикация на GitHub Pages

Репозиторий содержит готовый workflow `.github/workflows/deploy.yml`:

1. Создайте репозиторий на GitHub и отправьте код в ветку `main`.
2. В настройках репозитория откройте **Settings → Pages** и выберите источник **GitHub Actions**.
3. При каждом `push` в `main` запускаются шаги: установка зависимостей → проверка типов → автотесты → валидация аудиокаталога → сборка Vite (`VITE_BASE_PATH=./`) → публикация артефакта на `https://<username>.github.io/<repository>/`.

Маршрутизация построена на hash-URL (`#/catalog`, `#/setup`, `#/quiz`, `#/stats`), поэтому обновление страницы на GitHub Pages не приводит к ошибке 404.

## Права на код и аудиозаписи

- **Исходный код** и **аудиоматериалы** являются отдельными сущностями с точки зрения прав.
- В папке `public/audio/` размещены рабочие MP3-записи аудиотеки, прошедшие автоматическую проверку имён.
- Перед публикацией на GitHub Pages убедитесь, что права на открытое распространение всех размещённых записей подтверждены: GitHub Pages является публичным хостингом, и опубликованные MP3-файлы доступны посетителям сайта.
- Учитывайте лимиты GitHub Pages (опубликованный сайт до 1 ГБ, отдельные файлы в репозитории — до 100 МиБ).
